# PayRecover AI: Devpost submission draft

**Tagline (under 200 characters):**
An AI agent that finds money merchants lose on PayPal, proves it with PayPal's own records, and recovers it with one approved click.

---

## Inspiration

A store's "Payment complete" page is only the store's opinion. Bugs quietly turn it into lost money: an
approved PayPal payment that is never captured, an order marked paid that PayPal never charged, a price the
browser was allowed to change, a cart charged twice. Small merchants rarely notice until a buyer opens a
dispute or the month's numbers don't add up. We wanted an agent that checks every claim against the one
record that can't be wrong, **PayPal's**, and then actually gets the money back.

## What it does

PayRecover AI watches a store's orders and compares what the store *says* with what *PayPal recorded*.

- **Finds four kinds of leaks:** never captured, fake paid, wrong amount, duplicate charge. Plus the reverse,
  **payments PayPal took that the store never recorded** (from PayPal's transaction list).
- **Ranks them by urgency:** an approved payment still waiting to be captured comes first, with a live
  "waiting since" clock from PayPal's own timestamp.
- **Proves each one:** a printable evidence pack with the store's record next to PayPal's, every check, and a
  SHA-256 fingerprint.
- **Recovers the money after approval:** captures the missed payment, refunds the duplicate, or invoices the
  buyer for the balance (with a polite note written by Gemini). Then it **reads PayPal again** to confirm the
  money really moved.
- **Ask PayRecover:** a chat where Gemini plans and calls tools itself, PayRecover's checks and **PayPal's
  Agent Toolkit**, shows every call, and can only *propose* money moves as Approve buttons.
- **Dispute defender:** reads PayPal disputes, links each to its order, re-checks it, and Gemini recommends
  "send evidence" or "accept the claim" with a draft message. The merchant edits and approves; PayRecover
  sends it and confirms with PayPal.
- **Real-time alerts:** verified PayPal webhooks plus Zapier send an alert, with a signed one-tap approve link,
  the moment a payment or dispute needs attention.
- **Security checks of the store:** price-tampering probe, reflected-XSS check, security headers and a full
  website scan, so the merchant sees the hole behind the leak.

## How we built it

| Part | Technology |
|---|---|
| PayPal record of truth | **PayPal Server SDK** (Python, generated by APIMatic) for Orders v2, captures and refunds |
| AI tools from PayPal | **PayPal Agent Toolkit** for disputes, transactions, invoices and orders, called by Gemini and by our code |
| Other PayPal APIs | Invoicing v2, Disputes v1 (provide evidence, accept claim), Transaction Search, Webhooks with signature verification |
| AI | **Gemini** (function calling for the agent, structured JSON for plans and explanations), with fallback models |
| Backend | Python, FastAPI, pydantic; 260+ automated tests across backend, stores and dashboard; ruff, eslint |
| Dashboard | React, Vite, **AG Grid** |
| Developer experience | OpenAPI spec that passes **APIMatic** validation with zero errors; generated PayRecover SDKs (Python, TypeScript, C#) and an API portal |
| Automation | **Zapier** for alerts and approve links |
| Demo | A clean "Main store" and a "Vulnerable store" with switchable real bugs, both on the PayPal Sandbox |
| Deploy | Docker, **Render** blueprint, GitHub Actions CI |

**The rule we designed around: the AI explains, plans and proposes, but never decides or moves money.** Leaks
come only from deterministic checks against PayPal. Every money movement needs the merchant's explicit
approval, is recomputed from PayPal at that moment, carries an idempotency key so a retry never charges or
refunds twice, and is verified by a fresh read of PayPal. The agent gets only read-only Agent Toolkit tools.

## Challenges we ran into

- **Telling a leak from a normal state.** A refunded capture first looked like "never captured"; a duplicate
  cart could be refunded twice. We now model PayPal's capture and refund states precisely and keep one refund
  per cart.
- **Linking a dispute to an order and a store.** PayPal disputes name a capture, not an order. We follow the
  capture to its order and tag each store's payments with a `custom_id`, so disputes, transactions and
  webhooks all land on the right store.
- **Permissions and tokens.** Invoicing kept returning 403 after it was enabled, because the cached token
  predated the change. We now retry once with a fresh token and explain how to enable a feature when PayPal
  refuses.
- **Reliable AI.** Models sometimes stall or return over-long answers. Fallback models, a per-attempt timeout,
  skipping a stalled model for two minutes, and trimming answers to the schema keep the agent responsive.
- **A Sandbox account registered in India** couldn't run the US checkout flows, so we set up a US Sandbox
  business app.

## Accomplishments that we're proud of

- Real money recovered end to end in the Sandbox: captured, refunded and invoiced, then verified with PayPal.
- An agent that uses **PayPal's own Agent Toolkit** while staying safe: proposals, not actions.
- A dispute workflow where the AI argues from evidence and the merchant keeps the final say.
- An API good enough to ship: zero APIMatic validation errors, generated SDKs and a portal.

## What we learned

- PayPal's record is a powerful source of truth, but you have to understand its states (approved, captured,
  partially refunded, disputed) to read it correctly.
- The best place for AI in payments is *between* the facts and the merchant: planning, explaining and drafting,
  with deterministic checks and human approval on either side.

## What's next for PayRecover AI

- **Connect any store:** Shopify and WooCommerce apps, plus the documented PayRecover Store API for custom stores.
- **Connect PayPal safely:** PayPal Partner onboarding, so merchants approve access on PayPal's own page.
- **Always-on agent:** scheduled scans and a daily summary.
- **A browser extension** that flags leaks right on the store's order pages.
- **Live mode** after PayPal review (today it is locked to the Sandbox on purpose).

## About the starting point

PayRecover AI started from our earlier open-source testing tool, TestPilot AI (website and API checks). During
the hackathon we built everything payment-related: the PayPal integration, leak detection, recovery and
verification, the agent and Agent Toolkit integration, disputes, webhooks, evidence packs, the stores, Zapier
alerts and the APIMatic SDKs.
